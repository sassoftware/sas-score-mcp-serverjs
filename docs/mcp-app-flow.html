How MCP Apps work in sas-score-mcp-serverjs

A tool can return an interactive view instead of only text. The server ships one small web page; the host shows it next to the tool result and feeds it the data. Clicks in the view become new chat prompts, so the model (and its skills) stay in control.

requestresponse / datauser actionhost actionloop

The three pieces

1. Tool links to a view

A tool spec with ui: true is registered with registerAppTool, which adds _meta.ui.resourceUri. Other tools stay plain.

2. Server serves the view

registerAppResource exposes ui://sasmcp/view.html with mime type text/html;profile=mcp-app. It is one Vite-built single file.

3. Tool returns two payloads

content is text for the model. structuredContent (viewHint, columns, rows, paging) is for the view.

Good to know

Graceful fallback

Hosts without MCP Apps support ignore the metadata and just show the text content.

Why prompts, not direct calls

Buttons use app.sendMessage, so the model sees every step and its skills still steer the flow. Direct callServerTool would skip that.

Caching

The host reads the view once per URI and caches it. After adding ui: true to a tool, reload VS Code or restart the server to refresh the tool list.
