MCP Apps: tools that return a view

How a SAS tool result becomes a table you can click.

Team walkthrough
Why

A text answer is hard to scan and impossible to click

Before

Plain text result

The model reads rows as JSON and re-types them into chat. Long tables wrap badly, numbers lose alignment, and follow-up questions mean typing again.

With MCP Apps

An interactive view next to the result

The same tool call also returns data for a small web page. The host renders it as a table or a pick list, and a click becomes the next prompt.

The text result is still returned, so hosts without MCP Apps support lose nothing.

The idea

Three pieces make it work

1. LinkA tool with ui: true is registered with registerAppTool. That adds _meta.ui.resourceUri to the tool.
→
2. ServeregisterAppResource exposes ui://sasmcp/view.html: one Vite-built HTML file, mime type text/html;profile=mcp-app.
→
3. ReturnThe tool returns content for the model and structuredContent for the view.

One view for every tool

All tools point at the same view. It picks its layout from structuredContent.viewHint, so a new tool only has to return the right shape.

The payload

One tool result, two audiences

// returned by read-table
{
  content: [{ type: 'text',
    text: 'Read 20 rows from cars' }],
  structuredContent: {
    viewHint: 'table',
    columns: ['Make', 'MSRP', ...],
    rows: [['Audi', 36945], ...],
    count: 20,
    paging: {
      nextPrompt: 'read the next 20 rows',
      previousPrompt: 'previous 20 rows',
      hasPrevious: false, hasNext: true
    }
  }
}

content

Short text. The model reads this and nothing else. It also works on hosts with no MCP Apps support.

structuredContent

Data for the view: what to draw, the rows, and which prompts the buttons send.

Design choice

Buttons send prompts, not tool calls

What we do

app.sendMessage

The click posts text such as list tables in cas library Samples to the chat. The model sees it, applies its skills, and calls the tool.

What we avoided

app.callServerTool

Faster and updates in place, but the model never sees the new page and the skills that steer the flow are skipped.

Example: drilling down

list-libraries → click Samples → list tables in cas library Samples → list-tables → click cars → read Samples.cars → read-table

Good to know

Things that surprised us

VS Code caches tools

After adding ui: true to a tool, reload the window or restart the server. Otherwise the old tool list stays.

The view loads once

resources/read shows up in the log for the first tool only. Later tools reuse the cached HTML.

Paging depends on the model

The next prompt asks the model to move the offset. Telling it the table and row range in the text result makes that more reliable.

Check the host first

The server logs the client's capabilities on connect. Look for io.modelcontextprotocol/ui to confirm the host supports MCP Apps.
